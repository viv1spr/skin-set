Здесь можно добавить в конструктор всё, чего ещё нет: новые кейсы, перчатки, ножи. Цвета определяются автоматически по картинке, цена — по редкости (ориентир по уровням).

Справка

1. Токен GitHub (один раз)

GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Repository access: Only select repositories → skin-set. Permissions → Repository permissions → Contents: Read and write. Срок — максимум (1 год). Скопируй токен и вставь по кнопке «Токен» вверху. Он хранится только в этом браузере.

2. Вход в Firebase для модерации ленты

Firebase Console → Build → Authentication → Get started → Sign-in method → Google → Enable (укажи почту поддержки) → Save. Затем Authentication → Settings → Authorized domains → Add domain → skin-set.com.

Потом Firestore → Rules → замени на это и Publish (удалять сможет только твоя почта):


    
3. Переводы статей
Статья пишется по-русски. В редакторе кнопка «Перевести на все языки» переводит её на EN/DE/PT/TR/PL (нужен Anthropic API key в «Настройках»), после чего переключатель «Язык» показывает и даёт поправить каждую версию. При публикации страницы создаются во всех языках, где есть перевод, с перекрёстными hreflang. Без перевода статья выходит только на русском.
3а. Новые скины после апдейтов CS2
Вкладка «База скинов» → «Добавить недостающие»: админка возьмёт все скины из открытой базы, которых нет в конструкторе, определит цвета по картинкам (3–6 минут в фоне, вкладку не закрывай) → «Сохранить в репозиторий». Через пару минут новые перчатки, ножи и оружие появятся в подборе. Если база скинов устарела (новый кейс не виден) — напиши Claude, он обновит файл admin/skins-api.json.
4. Как публикуются посты

    
Админка записывает файлы прямо в репозиторий GitHub: blog/<slug>/index.html, список blog/index.html, blog/rss.xml, sitemap.xml и базу постов blog/posts.json. GitHub Pages пересобирает сайт за 1–2 минуты. После публикации открой Search Console → Проверка URL → «Запросить индексирование».
